# JWT Validation and Claims Extraction (Spring Boot)

A small Maven project for the lab task:
- Validate a JWT signature using a secret key.
- Reject expired or invalid tokens.
- Extract claims such as username (`sub`) and role.
- Test the API with Postman.

## Requirements
- JDK 17 or newer
- Maven (or use the Maven wrapper generated by your IDE)
- Internet access on the first build so Maven can download dependencies

## Run in IntelliJ / Spring Tool Suite / VS Code
1. Extract this ZIP.
2. Open the `jwt-validation-claims` folder as a Maven project.
3. Wait for Maven dependencies to download.
4. Run `JwtValidationApplication.java`.
5. The server starts at `http://localhost:8080`.

Command line (from the project folder):
```bash
mvn spring-boot:run
```

## Test using Postman

### 1. Generate a token (helper endpoint)
- Method: `POST`
- URL: `http://localhost:8080/api/jwt/generate`
- Body -> raw -> JSON:
```json
{
  "username": "abc"
}
```
Copy the `token` value from the response.

### 2. Validate token and extract claims (main exam endpoint)
- Method: `POST`
- URL: `http://localhost:8080/api/jwt/validate`
- Body -> raw -> JSON:
```json
{
  "token": "PASTE_TOKEN_FROM_GENERATE_RESPONSE"
}
```

Expected success response:
```json
{
  "status": "Token Valid",
  "username": "abc",
  "claims": {
    "sub": "abc",
    "role": "USER",
    "iat": 0,
    "exp": 0
  }
}
```
`iat` and `exp` values are timestamps; actual values will differ.

For an invalid/tampered token, the API responds with HTTP 401 and:
```json
{
  "status": "Invalid Token"
}
```
For an expired token, it responds with HTTP 401 and:
```json
{
  "status": "Token Expired"
}
```

## Important files
- `JwtValidationApplication.java`: starts Spring Boot.
- `JwtUtil.java`: creates tokens and validates signature/expiration; extracts claims.
- `JwtController.java`: exposes `/generate` and `/validate`.
- `application.properties`: port and demo secret.

## Viva notes
- **Signature validation:** verifies that the token was signed with the configured secret.
- **Expiration validation:** the parser rejects a token after its `exp` time.
- **Claims extraction:** `getPayload()` returns the claims; `getSubject()` reads the username.
- **Tampering:** changing token content without the signing key causes validation to fail.

## Security note
The included secret is for local lab demonstration only. Do not use it in a deployed application. In real projects, store secrets in environment variables or a secret manager and use suitable authentication and authorization controls.
